# 题目整理操作说明

本文是维护 `题目.md` 的操作索引。后续整理本目录题目时，优先阅读本文，再按目录行号跳转到目标区域，不需要通读整份题库。

## 一、文件职责

- `题目.md`：保存题目正文、目录、来源和待核对信息。
- `题目整理操作说明.md`：保存固定的整理规则和修改流程，不保存具体题面。

## 二、固定结构

每道题按以下顺序排列：

1. 二级标题：`## 序号. 题目名称`
2. 整理状态
3. 原始来源链接
4. `### 题目描述`
5. `### 输入格式`
6. `### 输出格式`
7. `### 输入样例`、`### 输出样例`，或合并为 `### 输入输出样例`
8. `### 核对备注`；存在缺失时增加 `### 待补信息`
9. `### 参考代码`；有参考代码时直接紧跟对应题面之后

目录必须位于正文之前，并包含：题面状态、参考代码、题面跳转、题目、当前行号、来源。题面跳转列使用 `[第 N 题](#标题锚点)`，题目列只保留名称，避免重复放置跳转链接。

目录前的摘要必须记录两个数量：当前 `题面状态` 为 `√` 的题目数量，以及 `参考代码` 为 `√` 的题目数量。新增加题目、完成题面或补充参考代码后，必须同步更新摘要、目录状态、题目行号和题面跳转链接。

新 agent 开始工作时，只需先读取本文件，再读取 `题目.md` 的摘要和目录；根据目录中的题面跳转与行号，直接定位目标题目区域，不要通读整份题目文件。若任务是补题面，查看 `题面状态` 不为 `√` 的行；若任务是补参考代码，查看 `参考代码` 不为 `√` 的行。

## 三、整理流程

1. 读取目录前摘要和目录表，先确定完成数量以及需要处理的状态列。
2. 根据题面跳转或行号，只查看目标题目前后的小范围内容。
3. 使用题名、独特题面句子、样例和约束搜索网络；优先选择官方 OJ 或可追溯的原始题集。
4. 对照原始题面修正标题、题意、输入、输出、约束和样例。
5. 将网页复制产生的“复制”“输入描述:”等噪声改为标准 Markdown 标题。
6. 代码、输入输出和点阵图必须放入 fenced code block，并标注 `text`；不要用普通横线代替未知图案。
7. 无法唯一确认的信息保留原始可确认内容，并写入“核对备注”或“待补信息”，不得猜测补全。
8. 完成后更新题目状态、来源、目录行号、摘要数量和题面跳转；补充参考代码时，将代码放在对应题面之后，并同步更新 `参考代码` 列。

### 题目来源检索要求

当用户提供新的题目文字、截图或题目线索时，必须主动检索对应的原题链接，不限平台。检索顺序如下：

1. 提取题目标题、独特句子、数据范围、输入输出样例、特殊常数和分值等可检索信息。
2. 优先检索官方题库、学校或竞赛官网；其次检索洛谷、牛客、HDU、AcWing、Codeforces、AtCoder、蓝桥杯等 OJ；最后参考可追溯的博客、题集或题解页面。
3. 至少使用两组不同关键词组合；图片题目还要组合搜索题目标题、样例数字、约束和代码中的独特变量或常数。
4. 找到候选题目后，对照题意、输入格式、输出格式、约束和样例，不能只凭标题相似就认定来源。
5. 目录的“来源”列填写最可靠的原题链接；如果存在多个可靠平台，可保留官方来源并在“核对备注”补充其他链接。
6. 如果只能找到相似题、搜索结果摘要或用户回忆，必须标记为“待核对”，并记录候选链接及匹配依据，不得把猜测当作原题来源。

## 四、状态规则

- `题面状态` 为 `√`：来源明确，题面结构完整，输入输出和样例已核对。
- `待核对`：来源不唯一、图片或字符画丢失、约束或样例存在冲突。
- 只有在待核对事项全部解决后，才能改为 `√`。
- `参考代码` 列只有在仓库中存在对应可编译参考代码后填写 `√`，不能仅因为网上存在代码就填写。

## 五、每次修改后的检查

- 目录锚点是否与题目标题一致。
- 目录行号是否覆盖完整题目区域。
- 样例是否仍在代码块中，且没有把题面说明混入样例。
- 原始来源链接是否可访问，平台限制是否被误当成通用约束。
- 修改正文后，重新计算全文行号并更新目录。
